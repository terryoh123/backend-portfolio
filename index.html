상품별 재고연동/관리 메뉴 개발

운영 효율 개선 / 재고 관리 자동화 / 관리자 기능 고도화
프로젝트 개요
대형 고객사의 프로모션 및 운영 정책에 따라 특정 기간 동안 상품별·쇼핑몰별 재고 연동을 중지하거나 수동 재고 입력 요청이 빈번하게 발생했습니다. 기존에는 내부 개발자가 직접 DB 수정 및 소스 예외처리를 통해 대응했으나, 이를 고객사와 운영팀이 직접 관리할 수 있도록 재고연동/관리 메뉴를 구축했습니다.
문제 상황
  • 재고 연동 중지 및 수동 재고 입력 요청을 개발자가 직접 처리
  • DB 수정 및 코드 예외처리 방식으로 운영 리스크 존재
  • 반복적인 요청 대응으로 불필요한 공수 및 리소스 낭비 발생
해결 방식
  • 상품별 재고, 재고관리 여부, 변경이력을 확인할 수 있는 관리자 메뉴 개발
  • 수정 기능을 통해 재고 수동 입력 및 재고 연동 여부(ON/OFF) 제어 가능
  • 변경 이력을 history DB에 저장하고 화면에 노출
  • 최근 24시간 이내 변경 이력이 존재할 경우 점멸 UI로 표시
  • 초기 진입 시 재고 연동 중단 상품 우선 노출하여 빠른 대응 지원
  • 상품코드 검색 시 연동 중 상품 포함 전체 조회 및 수정 가능
  • 상품코드 / 고객사 코드 클릭 시 관련 상세 페이지로 이동 기능 제공
기술 포인트
  • product DB의 Y/N 컬럼을 기준으로 API 배치 실행 여부를 제어하는 구조 설계
  • 운영자가 직접 제어 가능한 Self-Service 관리 시스템 구축
  • 데이터 변경 이력 관리 및 UI 시각화를 통한 운영 가시성 강화
  • 기존 수동 처리 프로세스를 시스템화하여 안정성과 일관성 확보
성과
  • 반복적인 재고 수정 요청 대응 공수 대폭 감소
  • 개발자 개입 없이 고객사 및 운영팀이 직접 관리 가능
  • 수동 DB 수정 및 코드 예외처리 제거로 운영 안정성 향상
  • 재고 관리 프로세스 표준화 및 작업 속도 개선

택배사 송장 자동발번·출력·이력관리 시스템

택배 API 연동 / 비동기 처리 / 성능 개선 / 운영 안정화
프로젝트 개요
여러 택배사 API와 연동하여 송장 자동발번, 출력, 전송 결과 이력관리까지 처리하는 시스템을 개발하고 유지보수했습니다. 단순한 API 호출 수준이 아니라 대량 주문 처리 상황에서도 안정적으로 동작하도록 구조를 개선했습니다.
문제 상황
  • 명절 시즌 대량 주문 처리 시 순차 처리 구조로 인해 무한 로딩 및 타임아웃 발생
  • 택배사 API 호출 제한(Rate Limit)과 서버 리소스 병목이 동시에 발생
  • 실패 건의 확인 및 재전송이 어려워 운영팀과 고객사 대응 부담이 큼
해결 방식
  • 쉘 스크립트 기반 비동기 처리 구조 적용
  • Retry Logic과 실패 건 재처리 배치 도입
  • 송장 결과 출력 및 이력관리 로그 저장 기능 개발
  • 사용자가 실패 사유를 확인하고 재전송할 수 있는 운영 기능 추가
성과
  • 1000건 이상 동시 처리 상황에서 처리시간 30분 → 3분 수준으로 단축
  • 발번 성공률 70% → 95% 이상 개선
  • 고객사 클레임 감소 및 시스템 신뢰도 회복에 기여
