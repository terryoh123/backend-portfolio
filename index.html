문제 상황
  • 재고 연동 중지 및 수동 재고 입력 요청을 개발자가 직접 처리
  • DB 수정 및 코드 예외처리 방식으로 운영 리스크 존재
  • 반복적인 요청 대응으로 불필요한 공수 및 리소스 낭비 발생
해결 방식

  • 수정 기능을 통해 재고 수동 입력 및 재고 연동 여부(ON/OFF) 제어 가능
  • 변경 이력을 history DB에 저장하고 화면에 노출
  • 최근 24시간 이내 변경 이력이 존재할 경우 점멸 UI로 표시
  • 초기 진입 시 재고 연동 중단 상품 우선 노출하여 빠른 대응 지원
  • 상품코드 검색 시 연동 중 상품 포함 전체 조회 및 수정 가능
  • 상품코드 / 고객사 코드 클릭 시 관련 상세 페이지로 이동 기능 제공

  • Retry Logic과 실패 건 재처리 배치 도입
  • 송장 결과 출력 및 이력관리 로그 저장 기능 개발
  • 사용자가 실패 사유를 확인하고 재전송할 수 있는 운영 기능 추가
성과

템플릿 생성: 택배사마다 상이한 레이블 규격과 바코드 출력용 송장 템플릿 양식을 생성합니다.
출력 및 전송 실행: 주문 처리 상태에서 대상 건을 선택하여 운송장 발번을 자동 실행하고 라벨 출력을 수행합니다.
전송 이력 관리: API 송수신 로그, 성공/실패 여부와 상세 에러 원인을 파악하고 재시도할 수 있는 관리 대시보드

프로젝트 개요

이커머스 운영 환경에서 특정 프로모션이나 시즌 이벤트 시점에 맞춰 상품의 등록 및 수정(판매 여부, 재고, 가격 등) 작업을 수동으로 처리하던 리스크를 방지하기 위해, 사용자가 지정한 미래 시점에 상품 등록/수정 작업을 자동으로 스케줄링하여 다수의 쇼핑몰 API로 일괄 연동해주는 예약 처리 시스템을 설계하고 구현했습니다.

문제 상황
  • 이벤트 오픈 및 프로모션 시점에 맞춰 새벽이나 주말에 개발자가 직접 소스 변경 또는 DB 작업을 수기 처리
  • 일시적인 트래픽과 대량의 API 요청이 한꺼번에 몰릴 때 쇼핑몰 API의 제한 사항(Rate Limit)을 준수하지 못해 동시성 이슈 및 연동 누락 발생
  • 수행된 이력과 에러 로그를 확인할 수 있는 수단이 없어 장애 발생 시 신속한 원인 파악 및 재작업이 어려움
해결 방식
  • 작업 예약 등록 기능: 관리자 화면에서 원하는 일시, 대상 연동 몰, 예약 대상 상품 및 수정 데이터를 간편하게 지정하여 예약을 생성하는 프로세스 구축
  • 비동기 스케줄러 배치 구성: 주기적으로 예약 테이블을 감시하며 실행 대기 상태인 작업들을 수집하고, 비동기 처리를 기반으로 대상 쇼핑몰 API를 안전하게 호출하는 자동화 로직 구현
  • API 실행 로그 및 에러 트래킹: 전송 실패 건에 대한 API 응답 코드와 에러 메시지를 이력 DB에 상세히 저장하고 화면에 시각화하여 사용자가 직접 실패 사유를 인지하고 보완할 수 있도록 제어 구조 고도화
기술 포인트
  • 각 쇼핑몰 API 제한(Rate Limit)을 준수하면서 대량의 예약을 순차적/비동기적으로 처리하기 위해 대기열 큐 및 데이터 분산 수집 패턴 설계
  • 배치 구동 중 에러 발생 시 데이터 불일치를 방지하기 위한 DB 트랜잭션 관리와 작업 재시도(Retry) 로직 도입
  • 예약 작업의 상태(대기, 진행, 완료, 실패)를 명확히 구분하여 데이터 불일치 및 중복 전송 위험 제거
성과
  • 수동 상품 갱신에 수반되던 야간/주말 수작업 공수 대폭 절감
  • 연동 몰별 속도 제어를 통해 데이터 누락 및 통신 차단 장애 최소화
  • 상세 이력 화면을 제공하여 문제 상황 발생 시 즉시 복구 및 자체 디버깅 구조 정착
